Tiny strings guide user confidence. Examples of supportive, precise language.

## The Invisible Interface

The words in your UI are part of the design. Button labels, error messages, placeholder text, tooltips—they guide behavior and emotion as much as color and layout.

Bad microcopy creates friction. Good microcopy creates trust.

## Button Text That Works

**Vague**: "Submit" / "OK" / "Continue"

**Precise**: "Create Account" / "Save Changes" / "Send Message"

The label should tell users exactly what will happen. Specificity reduces anxiety.

## Error Messages That Help

**Hostile**: "Invalid input"

**Helpful**: "Email addresses need an @ symbol"

Tell users what went wrong and how to fix it. Error messages are moments of frustration—make them constructive.

## Placeholder Text

Placeholders aren't labels. They disappear when typing starts. Use them for format hints, not field names.

**Bad**: placeholder="Email"  
**Better**: placeholder="you@example.com"

And never rely on placeholder alone. Pair with visible labels.

## Confirmation Dialogs

**Risky**: "Are you sure?" [OK] [Cancel]

**Clear**: "Delete 3 items?" [Delete Items] [Keep Items]

Repeat the action in the button. Make consequences explicit. Destructive actions deserve extra care.

## Loading States

**Unhelpful**: "Loading..."

**Informative**: "Saving your changes" / "Finding nearby stores"

Tell users what the system is doing. It builds confidence that something is actually happening.

## The Investment

Good microcopy takes time. It requires understanding user context, testing actual comprehension, and iterating on feedback.

But the payoff is trust. And trust compounds.
